---
name: evidence-report
description: Analyze many uploaded files, web pages, images or videos and deliver an independent source-grounded report with figures, charts and citations.
---

1. Confirm the report objective and give the user the expected scope and time commitment before beginning evidence work. If the sources still need preprocessing, use the configured intake options to explain how to provide the missing materials. Read `prepare_source_overview(cursor=0)` through every `next_cursor`. Record failed or missing material and retain a compact coverage map for long reports.
2. Call `synthesize_source_overview` to establish the current snapshot and locate the coverage catalog. For preprocessed input, the catalog uses the source summaries from the supplied wiki index and paths to the briefs. Read relevant `level=high` briefs and follow `next_offset` as needed. When operating in explicitly configured legacy mode, follow the tool descriptions for generated summaries and supplementary web research.
3. Verify material claims with `read_source_evidence` using a source ID with a keyword, block ID or original locator. Keep exact returned block IDs for formal citations. Cite locations as export Markdown lines when original page numbers are unavailable. Inspect relevant source figures with `look` when available. In a long report, save an outline with chapter targets and initialize a compact `report-progress.md` in the report's directory under `/workspace/projects/` before drafting. Use `write_file` to initialize the progress file and `edit_file` to update it. Read it before each new chapter. After saving each chapter draft, update the progress file with the chapter status, draft path, findings, citations, shared terminology, unresolved issues and the next writing step. Put the latest completed work and the next step near the top for the reader. Keep the file suitable for sharing with the report requester. On continuation, resume from the saved files and verify that the source snapshot still matches.
4. Draft Markdown under `/workspace/projects/`. Keep the main text near the user's requested length, excluding the generated evidence appendix. Lead with findings, explain methods and scope, cluster by theme, and include disagreements or limits. Use tables or meaningful figures when they aid interpretation. Cite each material claim near the text as `[[source-id#block-id]]`, substituting actual IDs. Cite supplementary web evidence distinctly. View the evidence before quoting it or charting numbers.
5. When relevant source figures are available and the report explains a mechanical assembly, spatial relationship or motion, embed the figures that best show the parts and interfaces discussed. Place each figure beside the related explanation and name the original figure and what the reader should inspect in the caption. Include an annotated explanatory schematic if requested, alongside the source figures. Honor an explicit text-only request and keep figures within the user's source scope. Use `![Descriptive caption](source:source-id/asset-id)` to embed a source figure. For a bar chart from comparable values, add a fenced block labeled `chart` containing a JSON object with `title`, `unit`, and `data`. Each row has `label`, numeric `value`, and one exact citation in `evidence`. Check units, dates, scale and denominators first.
6. Assemble the saved chapters into the final draft and review transitions, duplication, source coverage and length. Cite supporting evidence throughout, including in charts and captions. Use `publish_report(validate_only=true)` to check rendering locally. When relevant source figures are central to the report, pass `require_source_figures=true` for validation and delivery, and check that the returned count `source_figures` matches the planned figures. Check the full draft against the user's requested sections and scope before sending the final report. Tell the user what was delivered and note any material coverage gaps.
