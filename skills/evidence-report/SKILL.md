---
name: evidence-report
description: Analyze many uploaded files, web pages, images or videos and deliver an independent source-grounded report with figures, charts and citations.
---

1. Confirm the report objective and give the user the expected scope and time commitment before beginning evidence work. If the sources still need preprocessing, use the configured intake options to explain how to provide the missing materials. Read `prepare_source_overview(cursor=0)` through every `next_cursor`. Record failed or missing material and retain a compact coverage map for long reports.
2. Call `synthesize_source_overview` to establish the current snapshot and locate the coverage catalog. For preprocessed input, the catalog uses the source summaries from the supplied wiki index and paths to the briefs. Read relevant `level=high` briefs and follow `next_offset` as needed. When operating in explicitly configured legacy mode, follow the tool descriptions for generated summaries and supplementary web research.
3. Verify material claims with `read_source_evidence` using a source ID with a keyword, block ID or original locator. Keep exact returned block IDs for formal citations. Cite locations as export Markdown lines when original page numbers are unavailable. Inspect relevant source figures with `look` when available. In a long report, save an outline with chapter targets and initialize a compact `report-progress.md` in the report's directory under `/workspace/projects/` before drafting. Use `write_file` to initialize the progress file and `edit_file` to update it. Read it before each new chapter. After saving each chapter draft, update the progress file with the chapter status, draft path, findings, citations, shared terminology, unresolved issues and the next writing step. Put the latest completed work and the next step near the top for the reader. Keep the file suitable for sharing with the report requester. On continuation, resume from the saved files and verify that the source snapshot still matches.
4. Before drafting, plan visuals around the main findings, even for a short report. Use `list_source_figures` on the most relevant sources to discover figures outside the text blocks you verified. Use `look` to inspect candidates, and select the figures that help readers understand the finding. Include at least one substantive source figure, chart or process diagram when the material supports one. Honor explicit text-only requests and omit decorative or unsupported visuals.
5. Draft Markdown under `/workspace/projects/`. Keep the main text near the requested length, excluding the generated evidence appendix. Cite claims near the text as `[[source-id#block-id]]` and identify supplementary web evidence. Place visuals next to the findings they explain. Use tables for precise comparisons and short Markdown blockquotes for conclusions or caveats that need emphasis.
   - **Source figure**. Put `![Descriptive caption](source:source-id/asset-id)` on its own line. Explain what to inspect in the caption. For mechanical, spatial or motion analysis, show the relevant original parts and interfaces when available.
   - **Bar chart**. Use a fenced `chart` block containing JSON with `title`, `unit`, and `data`. Each row has `label`, numeric `value`, and one exact citation string in `evidence`. Compare like-for-like measurements with matching units, periods and denominators.
   - **Process diagram**. Use a fenced `process` block containing JSON with `title` and an ordered `steps` array of 2–12 objects. Each step has `label`, `detail`, and an `evidence` array of 1–4 exact citation strings. For a proposed workflow, label it as a proposal and cite the facts informing each proposed step. Use a table for unordered relationships.
6. Assemble the saved chapters and review transitions, duplication, source coverage and length. Call `publish_report(validate_only=true, min_visuals=...)` with the planned number of figures, charts and diagrams. Inspect the returned `source_figures`, `charts` and `diagrams` counts against the plan. When original figures are central, also use `require_source_figures=true`. Correct missing or misrendered visuals and keep the same validation arguments when delivering. Tell the user what was delivered and note any material coverage gaps.
